# Prompt 03.1 — Estrutura do Projeto React e Dockerfile do Frontend

> **Ordem de implementação:** Primeiro sub-prompt do frontend. Implemente após todo o backend (02.x) e antes dos demais prompts do frontend (03.2–03.6).

---

## Objetivo

Configurar a estrutura base do projeto React + Vite + TypeScript, o `Dockerfile` multi-estágio do frontend e a configuração do cliente HTTP com Axios e proxy reverso.

---

## Contexto

O backend FastAPI já está rodando em `http://backend:8000` (rede interna Docker) ou `http://localhost:8000` (local). O `nginx.conf` e o `docker-compose.yml` já foram criados (Prompt 00). Este prompt cria o projeto React e o Dockerfile que faz o build e serve o resultado via Nginx.

---

## Escopo

Esta tarefa cobre **exclusivamente**:

- Scaffold do projeto com `npm create vite@latest frontend -- --template react-ts`.
- `frontend/Dockerfile` — multi-estágio: build (Node 20-alpine) + serve (nginx:alpine).
- `frontend/src/api/client.ts` — instância Axios configurada com baseURL e interceptor de token JWT.
- `frontend/src/App.tsx` — esqueleto básico com React Router.
- `frontend/vite.config.ts` — proxy de desenvolvimento para `/api` apontando para `http://localhost:8000`.
- Dependências: `react-router-dom`, `axios`, `lucide-react` (ícones).

---

## Restrições

> ⚠️ **Não altere nada além do que está descrito neste prompt.**
> Não crie páginas finais, componentes de chat, painel admin ou testes. Não modifique o backend ou modelos de dados.

- Imagem de build: **`node:20-alpine`**.
- Imagem de serve: **`nginx:alpine`**, copiando o `nginx.conf` criado no Prompt 00.
- A `baseURL` do Axios deve ser `/api` (o Nginx ou o Vite proxy encaminham para o backend).
- O token JWT deve ser lido do `localStorage` e injetado via header `Authorization: Bearer <token>`.

### `frontend/Dockerfile`

```dockerfile
# Estágio 1: Build
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Estágio 2: Servir com Nginx
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### `frontend/vite.config.ts`

```typescript
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  server: {
    port: 5173,
    proxy: {
      '/api': {
        target: 'http://localhost:8000',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, ''),
      },
    },
  },
})
```

### `frontend/src/api/client.ts`

```typescript
import axios from 'axios'

const api = axios.create({
  baseURL: '/api',
})

api.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

export default api
```

## Notas de Implementação

- **Scaffold manual:** a máquina não possui Node/npm/Docker instalados no PATH. O scaffold foi criado manualmente, fiel ao template `react-ts` do Vite 6 (React 19, TypeScript ~5.7, ESLint 9), e as verificações foram executadas com um Node 24 local (instalado via pip `nodejs-wheel-binaries`, apenas para tooling — nenhuma dependência do projeto).
- **package-lock.json:** gerado com `npm install` — obrigatório para o `npm ci` do estágio de build do Dockerfile. Versões pinadas: axios ^1.7.9, react-router-dom ^7.1.1, lucide-react ^0.469.0, vite ^6.0.5.
- **Rotas do esqueleto:** apenas `/` (placeholder de boas-vindas) e `*` (NotFound). As rotas de chat/admin entram nos prompts 03.2–03.5.
- **Verificações executadas localmente:** `npm run build` (tsc + vite, sem erros de tipagem), `npm run dev` (Vite no 5173) e proxy validado com o backend uvicorn local: `GET /api/health` → `{"status":"ok"}` e `POST /api/auth/admin/login` com rewrite correto do prefixo `/api`.
- **Docker não disponível:** o critério `docker build` não pôde ser executado nesta máquina (Docker ausente). O Dockerfile segue exatamente o especificado; validar com `docker build -t empresta-frontend ./frontend` em ambiente com Docker.
