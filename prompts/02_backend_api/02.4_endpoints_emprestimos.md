# Prompt 02.4 — Endpoints de Empréstimos e Devoluções

> **Ordem de implementação:** Quarto sub-prompt do backend. Implemente após 02.1, 02.2 e 02.3.

---

## Objetivo

Implementar os endpoints REST para registro de empréstimos, listagem de empréstimos ativos e registro de devoluções. A lógica de negócio inclui subtração de estoque ao emprestar e restauração ao devolver.

---

## Contexto

A estrutura, autenticação e CRUD de equipamentos já existem (02.1–02.3). Os modelos `Cliente`, `Emprestimo` (emprestimos.db) e `Equipamento` (estoque.db) já existem (Prompts 01.x). Este prompt adiciona o fluxo completo de empréstimo/devolução. O prazo de devolução é definido pelo administrador em dias no momento do registro.

---

## Escopo

Esta tarefa cobre **exclusivamente**:

- `backend/app/schemas/emprestimo.py` — Pydantic schemas.
- `backend/app/services/emprestimo_service.py` — lógica de negócio (subtrair/restaurar estoque).
- `backend/app/routers/emprestimos.py` — 3 endpoints.
- Registrar o router em `backend/app/main.py`.

---

## Restrições

> ⚠️ **Não altere nada além do que está descrito neste prompt.**
> Não implemente o endpoint de chat, modelos de dados, Dockerfiles ou frontend.

- `POST /emprestimos` e `PUT /emprestimos/{id}/devolver` são protegidos por token de **admin**.
- `GET /emprestimos` é protegido por token de **admin**.
- A subtração de quantidade no `estoque.db` deve verificar disponibilidade antes de subtrair.
- Se a quantidade solicitada for maior que a disponível, retornar **409 Conflict**.
- Na devolução: marcar `devolvido=True`, preencher `data_devolucao=hoje`, restaurar quantidade no estoque.
- O `prazo_devolucao` é calculado como `data_emprestimo + timedelta(days=prazo_dias)`.

---

## Endpoints

| Método | Rota                            | Descrição                         | Status |
|--------|---------------------------------|------------------------------------|--------|
| GET    | `/emprestimos`                  | Lista empréstimos ativos (admin)   | 200    |
| GET    | `/emprestimos/me`               | Empréstimos ativos do próprio cliente autenticado (role=cliente) | 200 |
| POST   | `/emprestimos`                  | Registra novo empréstimo (admin)   | 201    |
| PUT    | `/emprestimos/{id}/devolver`    | Registra devolução (admin)         | 200    |

### `backend/app/schemas/emprestimo.py`

```python
from datetime import date
from pydantic import BaseModel

class EmprestimoCreate(BaseModel):
    equipamento_id: int
    quantidade: int
    nome: str              # nome completo do cliente
    email: str
    telefone: str
    matricula: str
    prazo_dias: int = 30   # definido pelo admin

class ClienteInfo(BaseModel):
    """Dados fornecidos pelo cliente ao agente, exibidos ao admin no painel.
    Nunca inclui senha_hash."""
    id: int
    nome: str
    email: str
    telefone: str
    matricula: str

    model_config = {"from_attributes": True}

class EmprestimoResponse(BaseModel):
    id: int
    cliente_id: int
    equipamento_id: int
    nome_equipamento: str
    quantidade: int
    data_emprestimo: date
    prazo_devolucao: date
    devolvido: bool
    data_devolucao: date | None
    cliente: ClienteInfo   # dados do cliente aninhados (relação do modelo)

    model_config = {"from_attributes": True}
```

### `backend/app/services/emprestimo_service.py`

```python
from datetime import date, timedelta
from sqlalchemy.orm import Session
from fastapi import HTTPException, status
from app.models.estoque import Equipamento
from app.models.emprestimos import Cliente, Emprestimo
from app.schemas.emprestimo import EmprestimoCreate


def registrar_emprestimo(
    body: EmprestimoCreate,
    estoque_db: Session,
    emprestimos_db: Session,
) -> Emprestimo:
    # 1. Verificar equipamento
    eq = estoque_db.query(Equipamento).filter_by(id=body.equipamento_id).first()
    if not eq:
        raise HTTPException(status_code=404, detail="Equipamento não encontrado.")

    # 2. Validar cliente ANTES de tocar no estoque (evita subtrair e perder unidades
    #    quando o cadastro não existe)
    cliente = emprestimos_db.query(Cliente).filter_by(matricula=body.matricula).first()
    if not cliente:
        raise HTTPException(status_code=404, detail="Cliente não encontrado. Realize o cadastro primeiro.")

    # 3. Verificar disponibilidade e subtrair do estoque
    if eq.quantidade < body.quantidade:
        raise HTTPException(
            status_code=status.HTTP_409_CONFLICT,
            detail=f"Estoque insuficiente. Disponível: {eq.quantidade}.",
        )
    eq.quantidade -= body.quantidade
    estoque_db.commit()

    # 4. Criar registro de empréstimo
    hoje = date.today()
    emprestimo = Emprestimo(
        cliente_id=cliente.id,
        equipamento_id=eq.id,
        nome_equipamento=eq.nome,
        quantidade=body.quantidade,
        data_emprestimo=hoje,
        prazo_devolucao=hoje + timedelta(days=body.prazo_dias),
    )
    emprestimos_db.add(emprestimo)
    emprestimos_db.commit()
    emprestimos_db.refresh(emprestimo)
    return emprestimo


def registrar_devolucao(
    emprestimo_id: int,
    estoque_db: Session,
    emprestimos_db: Session,
) -> Emprestimo:
    emprestimo = emprestimos_db.query(Emprestimo).filter_by(id=emprestimo_id).first()
    if not emprestimo:
        raise HTTPException(status_code=404, detail="Empréstimo não encontrado.")
    if emprestimo.devolvido:
        raise HTTPException(status_code=400, detail="Empréstimo já devolvido.")

    # Restaurar estoque
    eq = estoque_db.query(Equipamento).filter_by(id=emprestimo.equipamento_id).first()
    if eq:
        eq.quantidade += emprestimo.quantidade
        estoque_db.commit()

    # Marcar como devolvido
    emprestimo.devolvido = True
    emprestimo.data_devolucao = date.today()
    emprestimos_db.commit()

    # Ciclo do cliente concluído: remover seus dados da base se ele não tem
    # outros empréstimos ativos (regra de negócio: sem necessidade de manter
    # o cadastro após a devolução).
    _remover_cliente_sem_emprestimos_ativos(emprestimos_db, emprestimo.cliente_id)

    emprestimos_db.expire_all()
    emprestimos_db.refresh(emprestimo)
    return emprestimo
```

> A função auxiliar `_remover_cliente_sem_emprestimos_ativos` conta os empréstimos ativos do
> cliente e, se não houver nenhum, remove o registro de `clientes` **diretamente na tabela**
> (`Cliente.__table__.delete()`), sem passar pela relação ORM — expurgar o objeto via
> `session.delete` tentaria setar NULL na FK dos empréstimos devolvidos preservados
> (coluna `NOT NULL`). O histórico dos empréstimos devolvidos permanece no banco com
> `cliente_id` órfão.

### `backend/app/routers/emprestimos.py`

```python
from fastapi import APIRouter, Depends, status
from sqlalchemy.orm import Session, joinedload
from app.database.estoque_db import get_estoque_db
from app.database.emprestimos_db import get_emprestimos_db
from app.models.emprestimos import Emprestimo, Cliente
from app.schemas.emprestimo import EmprestimoCreate, EmprestimoResponse
from app.services.emprestimo_service import registrar_emprestimo, registrar_devolucao
from app.dependencies import get_current_admin, get_current_cliente

router = APIRouter(prefix="/emprestimos", tags=["Empréstimos"])


@router.get("", response_model=list[EmprestimoResponse])
def listar_emprestimos(
    estoque_db: Session = Depends(get_estoque_db),
    emprestimos_db: Session = Depends(get_emprestimos_db),
    _: dict = Depends(get_current_admin),
):
    return (
        emprestimos_db.query(Emprestimo)
        .options(joinedload(Emprestimo.cliente))  # dados do cliente p/ exibição no painel
        .filter_by(devolvido=False)
        .all()
    )


@router.get("/me", response_model=list[EmprestimoResponse])
def meus_emprestimos_ativos(
    emprestimos_db: Session = Depends(get_emprestimos_db),
    payload: dict = Depends(get_current_cliente),
):
    """Empréstimos ATIVOS do próprio cliente autenticado (role=cliente).
    O vínculo é feito pela matrícula do token -> cliente -> empréstimos."""
    matricula = payload.get("sub")
    cliente = emprestimos_db.query(Cliente).filter_by(matricula=matricula).first()
    if not cliente:
        return []
    return (
        emprestimos_db.query(Emprestimo)
        .options(joinedload(Emprestimo.cliente))
        .filter_by(cliente_id=cliente.id, devolvido=False)
        .order_by(Emprestimo.prazo_devolucao)
        .all()
    )


@router.post("", response_model=EmprestimoResponse, status_code=status.HTTP_201_CREATED)
def criar_emprestimo(
    body: EmprestimoCreate,
    estoque_db: Session = Depends(get_estoque_db),
    emprestimos_db: Session = Depends(get_emprestimos_db),
    _: dict = Depends(get_current_admin),
):
    return registrar_emprestimo(body, estoque_db, emprestimos_db)


@router.put("/{id}/devolver", response_model=EmprestimoResponse)
def devolver_emprestimo(
    id: int,
    estoque_db: Session = Depends(get_estoque_db),
    emprestimos_db: Session = Depends(get_emprestimos_db),
    _: dict = Depends(get_current_admin),
):
    return registrar_devolucao(id, estoque_db, emprestimos_db)
```

- [x] `POST /emprestimos` subtrai quantidade do estoque e cria registro (201).
- [x] `POST /emprestimos` com estoque insuficiente retorna 409.
- [x] `PUT /emprestimos/{id}/devolver` devolve e restaura estoque (200).
- [x] `GET /emprestimos` lista apenas empréstimos com `devolvido=False`.
- [x] `POST /emprestimos` com cliente não cadastrado retorna 404 **sem alterar o estoque**.

      com nome, email, telefone e matrícula — para o painel exibir **quem está com o equipamento**
      (validado com teste de integração; `senha_hash` nunca é exposto).
- [x] `PUT /emprestimos/{id}/devolver` **preserva o cadastro do cliente**: o cliente permanece na
      base com o mesmo ID e login ativo, independentemente de ter empréstimos (regra vigente:
      cadastro permanente). A devolução restaura estoque e marca o registro como devolvido.
- [x] `GET /emprestimos/me` retorna apenas os empréstimos **ativos do próprio cliente autenticado**
      (vínculo pela matrícula do token → `clientes` → `emprestimos`, `devolvido=False`), ordenados
      por prazo. Exige `role=cliente` (admin recebe 403); alimenta a página
      "Acompanhar empréstimos ativos" (prompt 03.4/nota) do frontend.

## Notas de Implementação

**Correção de integridade validada em produção (Docker):** o código literal do prompt subtraía o estoque **antes** de verificar se o cliente existia — um empréstimo com matrícula não cadastrada (ex.: vindo do chat) consumia 1 unidade do estoque silenciosamente, sem criar registro. A versão implementada acima valida o cliente primeiro e só depois verifica/subtrai o estoque. Critério extra adicionado e verificado (404 com estoque preservado).

**Dados do cliente na resposta:** a pedido do admin, o `EmprestimoResponse` passou a incluir o objeto
`cliente` (schema `ClienteInfo`: id, nome, email, telefone, matrícula) alimentado pela relação
`Emprestimo.cliente` do modelo — a listagem usa `joinedload` para evitar N+1. Motivação: controle de
empréstimos e ciência de quem está com cada equipamento. Validado com teste de integração
(`test_listar_emprestimos_inclui_dados_do_cliente`).

**Cadastro permanente do cliente (regra vigente):** inicialmente chegou-se a implementar a
remoção do cliente na devolução; o admin posteriormente definiu que o cadastro é **permanente** —
cliente segue com login ativo e ID vitalício, tenha ou não empréstimos. A remoção foi revertida;
os empréstimos devolvidos mantêm `cliente_id` preenchido. Validado com
`test_devolucao_mantem_cliente_na_base` (devolução → login 200 → mesmo ID).
